# Research rewrite plan

Date: 2026-11-02. Status: authorized implementation; scientific gates remain evidence-dependent.

## Deliverable and dependency order

Produce a reproducible empirical paper and audited data release answering whether foul history adds predictive value beyond known basketball context. The public scientific explorer follows the research release; a separate development notebook may expose explicitly labeled provisional evidence and synthetic diagnostics. A negative result is a valid endpoint.

1. **Foundation:** package and locked environment, project rules, research protocol, offline fixture/check command. Preserve the legacy release.
2. **Source ledger:** verified immutable files, game inventory, provenance and explicit missingness/failure reasons. Distinguish a source-observed inventory from independently verified schedule completeness.
3. **Canonical reconstruction:** one versioned event/possession contract, event references, classification reasons, audit flags, historical reconciliation. No silent migration of public rows.
4. **Independent audit:** comparison adapters and blinded review packet, random ordinary sample plus separately identified edge-case sample, independent review/adjudication, predeclared error tolerances and uncertainty. Automated fixtures are not film evidence.
5. **Descriptive mathematics:** exact WMI components and missingness, boundary tests, simulation scenarios including nonstationary independent rates, explicit uncertainty targets.
6. **Matched models:** reproduce the additive logistic benchmark, then compare regularized nonlinear context versus the identical context model with past history, training-only selection and feature-availability checks.
7. **Locked evaluation:** inventory prior data exposure, designate a genuinely unused cohort or collect future observations after protocol lock, specify a meaningful-effect threshold, paired clustered loss comparison and calibration. No adaptive reuse of protected data.
8. **Paper and explorer:** generated tables/figures, methods/data documentation, reproduction instructions, one declared public release and traceable game views.

## PR boundaries

Use `codex/research-foundation`, `codex/source-ledger`, `codex/canonical-possessions`, and `codex/reconstruction-audit` for the initial stack. Each PR targets its predecessor until merged; no automatic merge. Keep later research/model/publication work separate. Changes remain runnable at each boundary.

## Completion evidence

- Foundation: fresh install, lint, Python tests, website checks, wheel build, small offline pipeline.
- Source ledger: all declared bytes/hashes checked, path containment, deterministic output, source failures represented; no claim of complete seasons without independent schedule evidence.
- Reconstruction: strict validation, source-event traceability, hand-authored expectations for edge cases, documented quarantine, counts and discrepancies against historical outputs.
- Audit: annotation records with reviewer/source provenance, sampling design, uncertainty and adjudication; false/missing evidence must keep the release gate closed.
- Modeling/evaluation: only after audit; same test rows, past-only features, training-only tuning, convergence/calibration, uncertainty assumptions, frozen unused cohort and protocol.
- Publication: tables generated from an identified run, claims bounded by evidence, all upstream gates satisfied.

## Work that cannot be substituted with code

Independent footage annotation, an evidence-based scientific tolerance/meaningful-effect choice, and genuine non-exposure to evaluation outcomes require supporting evidence. Do not invent annotations, treat parser agreement as ground truth, or rename a previously explored season as prospective. Implement preparatory tooling while these remain unresolved; do not bypass the gates.
