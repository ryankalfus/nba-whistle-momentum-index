# Source ledger and event attribution

Version: `source-ledger-v1`. Date: 2026-11-02. This contract describes implementation evidence; it does not establish scientific validity or independent schedule completeness.

## Immutable inputs

`python -m whistle_research.sources verify --manifest MANIFEST --source-root CACHE --output NEW_DIRECTORY` checks every declared source's byte count and SHA256 using streaming reads. The manifest is a JSON list of objects with `file`, nonnegative integer `bytes`, lowercase `sha256`, and optional `url`. Paths are relative to the input directory; traversal, absolute paths, escaping symlinks, and duplicate paths fail closed. The ledger retains the manifest hash, expected and observed hash/size, and explicit `verified`, `missing`, `hash_mismatch`, `invalid_manifest`, or `invalid_source` status. No input bytes are edited.

`inventory` accepts the same arguments, plus optional `--schedule SCHEDULE` and `--schedule-provenance TEXT`. It rehashes each archive through the same open descriptor used for parsing, checks that hash against both declared expectations and the verification ledger, then streams regular CSV members inside the six explicitly mapped `cdnnba` archives without filesystem extraction. The mappings declare 2020 through 2024 archive labels as 2020-21 through 2024-25 regular seasons, and `cdnnba_po_2024` as 2024-25 playoffs. After parsing it drains the XZ stream to validate its trailer, rehashes that same descriptor, and checks descriptor/path identity and modification metadata. A changed/replaced input or truncated compressed stream fails the inventory and quarantines any diagnostic game rows already read. This detects changes during consumption; callers must still review and preserve the declared manifest as the trust anchor. Other files remain verified supporting inputs, but are explicitly skipped as non-declared event archives. The inspected box CSV is player/team statistics, attendance uses Basketball Reference identifiers, and assignments describe officials; none is silently promoted to an independent full schedule.

Commands create one new output directory exclusively. Existing directories are refused, including existing release directories. Outputs use sorted JSON keys, explicit schema/kind, and no machine-specific paths or wall-clock timestamp. A failed required hash, malformed archive/event, duplicate game/event, ordering anomaly, or schedule discrepancy produces nonzero exit status. An absent schedule permits an observed-only inventory with completeness explicitly `unverified`; it never establishes season completeness.

## Game inventory and provenance

Game IDs are decimal integer strings of at most ten digits, left-padded to ten digits. Fractional, missing, signed, or nonnumeric IDs are rejected. Type/season do not come from an inferred ID prefix. Each game/source/member row records `game_id`, `source_file`, verified `source_sha256`, `source_member`, declared `season`/`game_type`, `event_count`, and first/last source CSV row (header is row 1). Archive/member errors and invalid game-ID rows remain explicit in `source_failures`. Missing/duplicate action IDs and invalid/nonincreasing order numbers quarantine games. Repeated games across members/sources are flagged rather than silently merged. A partially consumed failed archive can retain diagnostic game rows; `source_failures` blocks acceptance of that inventory.

The downstream canonical event identity must retain `(game_id, source_file, source_sha256, source_member, source_row)`, the original `actionNumber` as source event ID, and original `orderNumber` as event order. Source rows are provenance, not a reconstructed chronological order. Preserve raw values and use explicit parser/version and reconciliation flags when chronology is corrected. The inventory checks numeric order without rounding and does not reconstruct possessions or decide eligibility.

## Independent schedule evidence

A JSON schedule is an object with nonempty `provenance` and a `games` list; a CSV schedule requires `--schedule-provenance`. CSV schedules reject duplicate/empty headers, missing required columns, inconsistent row lengths, and malformed CSV syntax instead of silently discarding identifiers or extra fields. Every row declares unique canonical `game_id`, `season`, `game_type`, and optional `status` (defaults to `expected`). Other statuses are `unavailable`, `excluded`, and `failed`; each requires an explicit `reason`. The schedule hash and provenance are retained. A supplied schedule is a declared evidence frame, not automatically independently validated truth; provenance must be reviewed separately.

With schedule evidence, coverage is `schedule_checked`. Expected absent games become `missing`; observed games outside the frame become `unexpected`; season/type disagreements become `metadata_mismatch`. Explicit unavailable/excluded/failed rows remain separately accounted for, with an `observed` flag. Observed excluded games receive disposition `excluded`, while observed unavailable/failed games receive `quarantined`. `accounted_for` means every frame row has an explicit accounting and no unexpected/metadata-mismatched games; it does not mean all games were downloaded, eligible, successfully parsed, or scientifically validated. Rule-based exclusions and quarantines never erase observations. Parser acceptance and the independent reconstruction audit remain separate gates.
